# 动态记忆更新

## 产品行为

不增加“记住”按钮。现有表达确认就是记忆反馈：

```text
用户表达 → 模型候选 → 用户确认正确 / 错误
                         ↓
             更新“表达 → 意图”映射置信度
                         ↓
               下一次向量检索与候选排序
```

- `final_confirm` 或有效的语音确认：记录正反馈。
- `reject_current_candidate`、`none_of_these`、`edit_completion`：记录负反馈。
- 选择候选但尚未最终确认不算正反馈；沉默、超时和模型置信度也不算。
- 一次用户操作只写一次反馈，接口重试不会重复计数。
- 记忆写入失败不阻断已经完成的表达确认，并在响应中返回失败状态。

## 两类个性化资料

1. **结构化人物档案**：保存用户明确填写或导入的稳定背景、关系、习惯和沟通
   偏好。产品统一展示为可信资料，不再区分 Gold / Silver。
2. **历史表达案例**：保存 `input_text`、`intent_text`、向量、正负反馈次数和
   置信度。它表示“这种表达过去通常对应这个意思”，不自动推断为稳定人物
   事实。

## 置信度与检索

演示版使用透明、可解释的增量规则：首次确认置信度为 `0.65`，每次正反馈
增加 `0.10`，每次负反馈降低 `0.20`，并限制在 `0.05–0.98`。负反馈惩罚更大，
避免错误案例靠少量重复迅速污染个性化结果。

系统为输入表达生成轻量的确定性向量。只有置信度不低于 `0.55` 的映射才进入
下一次检索；向量相似度决定匹配档位，映射置信度继续作为候选排序权重。低
可信映射仍保留在反馈记录中，便于后续纠正和审计，但不会影响模型提示。

演示版向量器不依赖外部模型，保证 mock 模式可复现；产品化时可以替换为正式
embedding adapter，而无需修改状态机和存储结构。

## 主要实现

- `core/personalization/dynamic_memory.py`：表达向量、相似度和置信度更新。
- `ExpressionMapping`：跨模块结构化模型。
- `expression_mappings`：聚合后的表达—意图映射。
- `expression_feedback_events`：按 session 幂等保存每次正负反馈。
- Web Demo session：把现有确认 / 拒绝命令直接转换为反馈，不提供二次确认
  API 或 UI。
- Profile registry：新 session 只合并超过阈值的映射，并保持 profile /
  patient 隔离。

## 比赛答辩简版

### 核心功能是如何通过技术实现的？

“我们把用户每次已有的确认动作直接作为监督信号，不额外要求用户点击
‘记住’。确认正确时，系统增强当前‘用户表达—目标意图’的映射；确认错误、
全部不对或进入修改时，则记录负反馈并降低可信度。稳定的人物信息放在结构化
档案中，历史表达案例以向量和置信度保存。下一次交互先做相似表达检索，再把
相似度和置信度共同用于候选排序，所以系统会随着使用逐渐适应个人表达习惯。”

### 遇到了什么技术难点，怎么解决的？

“主要难点是持续学习很容易把一次误识别放大成长期错误。我们的解决方式有
四点：只把用户明确的正确 / 错误操作当反馈，拒绝和修改不会成为偏好；负反馈
的降权幅度大于正反馈的增权；只有超过阈值的映射才参与检索；每条反馈按用户
和 session 隔离并做幂等记录。这样既能越用越懂用户，又能防止错误记忆污染
人物档案。”
